# 人工远程解锁 Mac：接入方案

2026-11-01。当前状态：电脑优先主界面、人工控制台、本地代理与外网认证已实现；59 项测试与构建通过。系统屏幕共享已启用，真实连接已到达 Mac 账户认证页并预填本机用户名；尚未输入真实系统密码，未通过真实 Mac 解锁与新弹窗操作验收。

## 结论与当前缺口

正常登录后的锁屏可以通过合适的远程桌面通道，由用户查看登录画面并手动输入 Mac 密码。此前“必须在本机解锁”的说法只描述了 Skyrail 当前应用窗口通道的限制，不能推广到 macOS 的所有远控方式。

Skyrail 的模型工具通过 ScreenCaptureKit 采集所选应用、通过 AX / 窗口输入操作该应用。这不等于系统屏幕共享，锁屏检测仍阻止模型使用这个通道。新增人工控制台独立连接系统屏幕共享。

本机：Apple silicon（arm64）、macOS 26.6.2。最初核对时屏幕共享关闭；后续核对已为 enabled，实际 RFB 探测成功。真实浏览器连接已收到系统 ARD 认证挑战，等待本人输入密码。代理与模型窗口工具保持分离，不通过删除锁屏检查来模拟解锁。

## 交互流程

1. 检测锁屏后，暂停模型电脑操作、释放按键与窗口连接，保留同一 Codex session 和聊天记录。
2. 首页直接显示整台 Mac 控制台，点击“连接 Mac”；尚未配置时显示系统屏幕共享设置路径。
3. 用户进入全桌面控制台。浏览器连接经过认证的 WebSocket 代理，再连接本机系统屏幕共享服务。用户在浏览器输入系统认证信息，必要时继续在登录画面手动输入密码。
4. 选择共享当前物理桌面会话；不能误接另一个用户或新建虚拟登录会话，否则解锁后 Codex 仍看不到原窗口。Apple 的会话选择行为必须实机验证。
5. 解锁后在同一画面操作新应用和弹窗。切到 Codex 对话会保留桌面连接；点击“结束控制”或在聊天中“交给 Codex”时，关闭人工通道并清除客户端凭证，再允许模型请求应用连接。不恢复旧的未完成点击。

人工通道包含整个桌面，手机应提供缩放、平移、屏幕键盘和特殊按键。密码阶段不经过聊天输入、模型工具或会话同步；不采集或记录此通道的画面、剪贴板与按键。服务器仅转发二进制流，不打印载荷。界面应说明整桌面共享范围。

## 技术路线与边界

- 使用 macOS 自带 Screen Sharing 服务，浏览器侧评估 noVNC。上游 `core/rfb.js` 已实现 ARD 用户名 / 密码认证；接入前固定可发布版本及完整性信息，验证本机提供的实际协议。不能把上游源码支持等同于本机登录成功。
- 新增受限 WebSocket → TCP 代理，目标固定为本机屏幕共享端口，禁止客户端传主机 / 端口，避免成为任意 TCP 代理。不要直接把 5900 映射到公网。系统服务开启后的局域网暴露范围也需检查与限制。
- 公网网关在 upgrade 时验证远程登录 Cookie、Host、严格 Origin、专用路径及有效控制租约；本地服务也独立验证令牌。拒绝缺失 Origin。连接独占，登出 / 租约失效 / 断线释放所有权，禁止自动重连后重放按键。
- 复用已有 HTTPS 域名，但新增 WebSocket 代理需单独测试 Cloudflare 转发。HTTPS 在 Cloudflare 终止，这不是浏览器到 Mac 的独立端到端加密承诺。
- noVNC 为 MPL-2.0，需保留其许可和第三方声明；Skyrail 自有代码的 MIT 许可不替代依赖许可。
- 保留模型锁屏闸门。人工解锁不属于模型的“允许全部操作”，也不应向 Codex 增加读取 / 保存 Mac 密码的工具。
- 系统屏幕共享的开启与允许用户配置，需要系统本人完成或明确授权；本轮没有修改这些设置。

## 区分三种情况

| 状态 | 处理方式 | 当前边界 |
| --- | --- | --- |
| 已登录后的锁屏 | 系统屏幕共享，用户远程输入密码 | 本方案的第一阶段目标，尚未实机通过 |
| 显示器熄灭 / 整机睡眠 | 显示器按需唤醒；整机睡眠需另有可达的唤醒机制 | 睡眠中的 Skyrail / tunnel 不能自己持续运行；不能用锁屏解锁替代唤醒 |
| 重启后的 FileVault 解锁 | 符合条件的 macOS 26 Apple silicon 可通过系统 SSH 密码认证解锁卷 | 不是 VNC 登录画面；需要事先开启 Remote Login，以及独立可达的网络路径 |

Apple 已记录 macOS 26 的 FileVault-over-SSH，因此“重启后绝对不能远程解锁”也不准确。但数据卷尚未解锁时，本项目目录中的 Node 服务和同机 Cloudflare tunnel 不能承担入口；不能承诺现有域名能直接恢复。此路径另行评估，不在第一阶段混入。

## 使用与部署

首次在 Mac 的「系统设置 → 通用 → 共享 → 屏幕共享」开启系统服务，仅允许自己的账户。无需启用允许任何人请求控制，也无需打开传统 VNC 密码。可通过系统防火墙 / 网络配置进一步限制系统服务的局域网范围。

升级依赖后运行 `npm ci`、`npm run build`，重启 Skyrail 服务及远程网关。网关重启会使远程登录 Cookie 失效，但不会改变访问密码；无需重编译或重新授权 Swift 辅助应用。

首页点击“连接 Mac”，使用自动预填的 Mac 用户名和自己的系统密码认证。如系统登录画面仍出现，再点按目标并通过“输入文字”输入。手机默认仅保留点按和输入，原尺寸 / 平移位于画面设置。连接最多 15 分钟；页面心跳失联 45 秒关闭，不自动重连或重放输入。Codex 应用工具在次级设置中，人工主路径使用整台 Mac 的系统共享。

本地开发者可在构建后运行 `node tests/fixtures/desktop-preview.mjs`。这是独立 loopback 模拟桌面，包含合成画面和接受虚构凭据的 ARD 测试握手，不能当作生产服务或输入真实账户密码。它不连接实际 Mac 或 Codex。
