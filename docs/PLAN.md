# Skyrail 实施计划

目标是完成设计稿中的单用户闭环：连接用户本地 Codex → 对话 → 隔离电脑 → 观看 → 接管 → 交还 → 文件 → 历史恢复。先验证运行时与输入安全，再完善桌面包装。原稿估计 5–8 周只作为初始范围参考。

## 已完成的起点

- [x] 项目命名、本地目录、Git 初始化、锁定 npm 依赖。
- [x] React 聊天及电脑演示面板，适配桌面与窄屏。
- [x] app-server stdio 适配器、真实聊天通道、错误和停止入口。
- [x] 服务端模拟控制状态与 epoch 冲突测试。
- [x] 本地记录、恢复线程入口、无自动副作用重试。

## M0 兼容验证

固定宿主 macOS、Codex 版本与 Linux 图形镜像。生成协议 schema，验证三轮真实聊天、进程重启恢复、取消、审批错误与图片输入。分别记录本地握手、真实模型回复、实际电脑观察的证据。选定 Cua Driver 精确版本并检查组件许可证，不引入 Cua 商业应用代码。

退出标准：有可复现的真实任务观察、操作与停止证据。当前仅聊天骨架，不能判定 M0 完成。

## M1 可靠会话

引入 SQLite 迁移、Thread/Run/Event/Command 表、事务去重与 seq 重连；补齐模型列表、审批卡、断线状态与 turn/steer 或明确排队。将请求超时和进程中断的结果未知独立建模。

退出标准：三轮对话和重启恢复通过；重复提交不启动第二个 turn；错误、审批、停止真实显示。

## M2 单台隔离电脑

固定 Linux 镜像与单任务目录；接入 Cua 观察工具和 noVNC 画面。先验证只读画面，再加文件索引和受限下载。工具必须绑定 thread / session，禁止直接暴露驱动入口。

退出标准：自建测试页内任务从消息到可下载产物完整跑通；不使用真实付款或发信测试。

## M3 控制权与恢复

执行端租约校验、TTL / 心跳、原子 epoch 比较、动作排空、清理键鼠状态、交还新截图；服务端过滤只读 RFB 写消息。区分画面断开、控制断开与 runtime 断开。所有迟到输入拒绝；结果未知先查询再恢复。

退出标准：设计稿 A02–A08、A10、A11 通过。双写、过期输入、串会话、重复提交或停止误报均阻断发布。

## M4 试用与包装

检查 1440×900、1280×800、1024×768、390×844 与 200% 缩放。补滚动锚点、分隔条键盘操作、主题对比、焦点恢复、数据删除、诊断与资源回收。再决定 Tauri/Electron，邀请五位用户验证。

退出标准：A01–A12 证据齐全，用户能分辨收起与暂停，回退和数据保留规则明确。

## 下一步优先顺序

1. 自动化 app-server schema 兼容测试及三轮/重启冒烟。
2. SQLite 与请求提交核对，关闭进程崩溃后重复执行风险。
3. 固定 Linux 镜像，先接只读画面与截图。
4. 引入执行端控制权后开放真实接管。
