# 设计依据

## 权限与文件入口 2026-11-03

在保持 Hark 风格、仅对话 / 电脑两页的前提下，将权限开关放在对话输入框设置中；“允许全部操作”默认开启，统一控制命令行 / 文件 / 网络与原生应用审批。系统隐私权限另列真实状态与设置入口。执行中的任务不能切换权限，切换后继续同一个 Codex session。

输入框增加文件夹入口，展开文件管理侧页；手机使用全宽抽屉。当前项目与上传文件分开显示，可多选上传、拖放、取消、查看进度、将已有文件加入消息及下载。待发送附件可移除，发送后作为消息附件保留。生成结果的项目链接直接下载，不增加第三个主导航。传输目录与校验边界见 SECURITY.md。

## 手机触控与共享范围 2026-11-01

本修订优先于下文较早的“人工仅走全桌面”与“单指滑动查看”说明。保留 Hark 风格、对话 / 电脑两页，电脑页内提供“整个桌面 / 单个 App”范围选择。单应用仍使用真实原生窗口串流，并恢复同一窗口的人工输入；完整桌面用于跨应用和系统弹窗。

手机默认采用触控板：滑动只移动光标，轻点点击、连点双击，第二次点按后移动才开始拖拽。第二根手指加入时进入视图手势，不把刚发生的点按误认成第二次远程点击。双指控制 1–4 倍缩放和画面平移，缩放后光标接近边缘时画面跟随；直接点按模式可在操作选项中切换。键盘只由显式按钮展开。

两种通道共用 SurfaceGestures / RemoteSurface，输入以缩放后图像的归一化坐标表示，保留空白区和宽高比的处理。桌面通过固定版本 noVNC 1.7.0 适配层编码指针包；应用通过现有 epoch / client / thread 校验队列发送。接管闸门、认证和目标范围不改变。noVNC 的全网页备用光标始终隐藏，由画面内受裁剪的光标替代；离开电脑页后停止接收输入和显示光标。

参考：[RealVNC mobile interaction](https://help.realvnc.com/hc/en-us/articles/360018541231-Using-RealVNC-Viewer-for-Mobile-to-control-a-remote-device)、[Jump Desktop gestures](https://support.jumpdesktop.com/hc/en-us/articles/216423503-Getting-Started-Jump-Desktop-Controls-and-Gesture-Reference)。仅参考手势约定，未复制界面源码。

## 最新修订：保留风格，简化交互

2026-11-01 用户修正：保留先前 Hark 风格，简化的是操作而非视觉。此要求取代下文早先的暖白重构和独立“会话”主导航。

- 仅有对话 / 电脑两页，手机底部也只有两项。管理对话按钮位于对话页，可展开最近记录与按项目分组的原生 Codex 会话。
- 还原天空蓝、雾色与浅桃渐变，半透明工作面与圆角输入框，保留轻盈留白。手机提供一键放大：放大后滑动查看，轻点操作，无需另选拖拽模式。
- 交给 Codex 不再拆掉桌面连接；服务端切为只看画面并阻断人工输入，交还先撤销模型操作再恢复点按。默认主操作只剩输入文字 / 接手操作。
- 真正断开收进电脑选项。系统的断开恢复锁屏策略由一次性管理员脚本处理，不通过每次控制授权、自动登录或收集 Mac 密码实现。
- 普通 Codex 会话按实际项目目录分组，Git 子目录和 worktree 归到原仓库，保留原 ID、原工作目录及分页能力。

## 当前交互方向：电脑优先

2026-11-01 用户明确要求：电脑控制突出、界面干净，手机只需点按与输入。此修订优先于下文较早的“聊天为主”和“选择应用窗口进行人工控制”描述。

- 首页直接呈现整台 Mac 的系统级桌面连接；Codex 对话与会话历史放在次级导航，应用工具连接进入设置。
- 人工点按与输入通过同一系统桌面通道覆盖新应用、弹窗和菜单。旧的按 PID / 窗口输入即使返回成功，也不能当作应用响应；不再作为主界面的人工控制路径。
- 手机默认只有画面、输入文字与结束控制，原尺寸 / 平移收进画面设置；移除原先显式滚动 / 拖拽模式。
- 账户名由受认证的本机接口读取并预填，密码不存入聊天或日志，浏览器只在当前认证过程中持有。
- 聊天保留同一个 Codex 会话与审批流程。浏览对话不会断开桌面；人工控制期间发送任务，会先结束控制、清除凭证，再交给 Codex。
- 统一浅雾色底、暖白工作面与深蓝按钮，深色模式共用语义颜色。手机采用底部导航、44px 按钮、可见键盘输入框和 visualViewport 高度适配。

原始文件：用户桌面 Codex_Desk_Product_Design_Architecture_v1.docx，版本 1.0，2026-10-29。原文件留在桌面，不随代码公开。

目标用户为已有 Codex 使用习惯的个人；主要任务是从连续对话进入电脑操作并可接手。视觉语气轻盈、平静、易读。

颜色按原稿：天空 #AFC9DD、雾色 #D7E1E4、浅桃 #F0DFCC；正文 #233A4B，辅助 #506779，按钮 #344F65。中文使用系统 PingFang SC，遵循原稿；正文 15px。核心布局是居中聊天，打开电脑后 40/60 分栏；1100px 以下切换单视图。电脑底板不透明，模拟画面持续标示。

没有把预设回复接入真实聊天。真实消息仅从运行时事件生成，未接入电脑的情况明确展示。当前页面是独立实现，未复制 Hark 或参考站点源码。

## 用户修订 2026-10-31

直接适配用户 Mac。原设计的 Linux 隔离环境、VNC 与远程画布输入不再实施。电脑区域改为应用选择、系统权限、真实窗口观察和逐次操作审批；人工操作直接发生在本机。状态文案持续区分截图、实时视频与未授权。

2026-11-01 补充：为人工远程解锁，新增浏览器 VNC 客户端连接本机 macOS 系统屏幕共享，不引入 Linux。它与模型的应用窗口通道分离，使用原生模态控制台隔离聊天焦点，显示整桌面范围与当前控制状态。系统服务关闭时给出设置路径；输入仅保留在当前连接，断开不重放。威胁模型与部署边界详见 [安全说明](../SECURITY.md) 和 [人工解锁](REMOTE-UNLOCK.md)。

## 触屏交互 2026-11-01

手机是直接触控，不复用“点一下就捕获桌面键盘”的路径。默认轻点发送一次点击，8px 以上手指移动进入滚动，不发送鼠标 down；拖拽通过显式模式提供。键盘由用户按钮唤起，并提供软键盘不便输入的 Tab / 回车 / 退格。多指介入、pointercancel、失焦和控制权变化会释放输入。网页其他区域仍保留正常浏览器交互；画面内不实现捏合缩放。

小屏工作区单视图，44px 触控目标、安全区域与横屏高度分别处理。浏览器尺寸模拟、触摸事件模拟、iOS / Android 真机兼容分别记录。

## 远程访问的信任边界

HTTPS tunnel 只接到带密码的 4318 网关。随机密码保存在忽略目录，Cookie 使用内存 HMAC 签名、Secure / HttpOnly / SameSite，并检查 Host / Origin、限制登录频率。威胁模型包括未登录访问与跨站请求；不提供多用户身份、OS 沙箱或被盗设备防护。应用内容和网页不能授予模型额外权限。相关实现与现有约束见 SECURITY.md 和 ARCHITECTURE.md。


## 桌面布局与连接恢复 2026-11-03

保留 Hark 的浅雾、暖白、深蓝与圆角风格。仅在宽度至少 1100px 时调整：顶部导航真正居中；聊天工作面 1040px、内容与输入区共用 840px 栏宽；设置浮层不挤压消息；电脑工作区 1320px。现有移动断点与操作布局不变。

连接冲突在原对话内恢复，先显示具体占用者及共享会话数量，再由用户结束占用连接；不以新建会话掩盖错误。该动作可能中断桌面端当前聊天，提示须明确保留。安全边界见 SECURITY.md。文件读取使用有时限的诊断，超时反馈保持不确定性，不要求用户反复上传已存在的本地文件。

## 图片对话 2026-11-03

输入框保留现有 Hark 样式与导航，新增“添加图片”入口；同一区域可粘贴截图或拖入文件。发送前显示可移除的缩略图，上传中显示进度与取消，完成前不允许发送残缺附件。消息图片可点开大图并下载，预览失败给出下载退路。手机预览限制在视口内，关闭与下载目标至少 44px，不新增导航页或改变电脑控制交互。

## 画质模式、手机浮窗与一次连接认证 2026-11-13

画质分为自动、高清优先、连接优先。自动判断统一在 RFB 适配层，慢帧或高 RTT 触发冷却期，成功心跳不能覆盖降级；手动选项保持固定。桌面与手机默认悬浮窗保留聊天，桌面可切换侧栏，两端可最大化。只有标题拖动区处理窗口移动，画面仍按原控制租约发送输入。放大、收起及侧栏切换不卸载串流组件。顶部导航在所有应用布局中保留 Skyrail、语言、主题入口。操作工具默认折叠，入口移至浮窗/侧栏标题栏；展开后的共享范围、键盘、回车、连接状态占独立区域，不覆盖远程像素。收起工具同步关闭软键盘并释放尚未抬起的输入，保持连接与控制租约。

屏幕共享与系统锁屏的认证不合并、不删除。只在用户明确勾选后，将首次成功认证的连接凭据保存到本机钥匙串；新建 helper 可独立编译，不重新签名主 Mac 应用。威胁模型包括未经认证的读取、旧连接复用、并发忘记/保存和密码日志泄漏。凭据读取要求已认证的 Skyrail 请求、同一浏览器的实际 RFB 认证阶段和一次性租约；保存要求 RFB 已认证。保存/读取/删除串行执行，密码仅通过 stdin 与 TLS API 在内存传递。锁住的钥匙串不弹系统窗口，退回手动输入；UI 可忘记记录。此方案仍依赖单用户网关、可信浏览器及本机账户，不能防止已完全控制主机的进程，也不会自动输入锁屏密码。


## 统一电脑入口与尺寸边界 2026-11-13

修复侧栏的根因是 dock 仍继承横向 flex，标题与画面并排；现在所有布局共享纵向 dock，桌面侧栏默认 440px，拖动分隔线调整，最大 880px，始终为聊天与间隔保留至少 296px。浮窗与侧栏尺寸独立记忆。

标题栏仅保留一个省略号菜单：显示方式、操作工具、调整窗口大小、收起。菜单和操作工具展开时占独立区域，远程画面按可用区域适配。两端“调整窗口大小”显示临时调整栏；拖动右侧手柄可改变宽高，完成后恢复简洁视图，手柄不占远程像素。分隔线与手柄同时支持方向键和 Shift 加速。

浮窗使用 CSS 像素和 visualViewport 边界；桌面最小 360×260，手机最小 260×180，上限 1120×900，实际边界以视口、导航栏、8px 边距为准。极小视口以可见区域优先。软键盘或旋转触发临时约束，恢复视口后回到用户尺寸；只有主动调整才保存偏好。切换布局和尺寸仍保留同一个工作区与串流实例。


## iPhone 输入与浮窗重叠修复 2026-11-14

用户提供的四张 iPhone 截图显示：Safari 输入时页面被平移、远程密码输入唤起系统填充、工具堆叠占满视频区域，以及半透明窗口透出聊天文本。此次采用固定页面与 visualViewport 高度/偏移同步，移动端输入字号至少 16px；远程文字输入改为关闭自动填充的 textarea，组合输入完成后才发送并立即清空，不保留输入记录。锁屏密码仍由所有者通过自己的查看器输入。

手机输入时隐藏共享范围、连接标题和设置栏；输入控件及特殊键留在画面外独立区域，极小高度下输入区可滚动，避免视频被挤成零高度。手机设置改为按需展开的不透明面板；浮窗、标题、菜单和控件均使用实色 token，保留页面的 Hark 渐变。聊天输入获得焦点且键盘弹出时，电脑浮窗临时隐藏，结束后恢复，串流组件保持挂载。

增加直接“缩小窗口”，手机最小尺寸降至 220×160（更小视口仍以可见边界为准）；缩小及开始调整大小时自动收起操作工具。验证覆盖中文组合输入不重复发送、IME 确认不误发回车、键盘收起与焦点释放、尺寸缩小/恢复，以及浏览器 400×360 与深色布局。iOS 实机键盘仍需所有者刷新后验收；浏览器仿真不作为 iOS 系统行为已验证的证据。


## 左侧电脑入口与双语 Chrome 演示 2026-11-14

电脑入口固定在屏幕左侧，展开后保持同一电脑图标，点击可收回；浮窗标题栏最左侧电脑图标独立为收起按钮，相邻拖动区只负责移动。此前图标属于拖动按钮，轻点没有动作。尺寸菜单逐次缩小，到最小尺寸后触发收起而非无反馈。收起保留挂载、布局偏好和已有连接，重新点击左侧入口恢复。

当前双语演示分别捕获英文/中文产品 UI、公开对话及 Chrome 内的 Orbit Studio 网页；桌面均使用浮窗，手机图片为模拟视口，数据均为虚构样例。示例网页源文件位于 website/demo/chrome-workspace.html。已通过原生 Chrome 操作实际渲染的手机视口：连续三次缩小，观察变小后收起，再从左侧按钮重新展开；这不是 iPhone 触控实机验收。
